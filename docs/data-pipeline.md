# Phase 2 — 데이터 수집 · 정제 · 분할

> 전체 일정의 **병목**. 모델 코드보다 여기가 오래 걸린다. 손으로 다운로드하지 말고 파이프라인을 돌린다.
> 용도는 **공모전(비상업)**. 출처·라이선스는 기록하되 데이터셋 자체는 재배포하지 않는다.

## 파이프라인 순서

```
(1) crawl_inat.py    iNaturalist API   → data/raw/<종>/inat_*.jpg   + licenses.csv
(2) crawl_search.py  Bing 키워드 크롤링 → data/raw/<종>/web_*.jpg
(3) dedup.py         phash 중복 제거
(4) prefilter.py     사전학습 모델로 비물고기 후보 걸러내기
(5) 사람 검수         썸네일로 오라벨·요리사진·여러마리 삭제 → data/clean/<종>/
(6) split.py         70/15/15 stratified → data/splits/{train,val,test}/<종>/
```

**모든 스크립트는 `src/config.py`의 `SPECIES`에서 학명·키워드·목표량을 읽어 쓴다.** 종 목록을 스크립트에 다시 적지 말 것.

## 소스 우선순위

| 순위 | 소스 | 특징 | 비고 |
|---|---|---|---|
| 1 | **iNaturalist / GBIF API** | 학명 라벨·라이선스·지오태그 포함, 전문가 검증(research grade) | 라벨 오염 거의 없음. 혼동 쌍은 여기서 우선 채운다 |
| 2 | **검색엔진 크롤링** | "○○ 낚시" 한글 키워드 → 손에 든/바닥/젖은 **실사용 유사 사진** | 라벨 오염 많음, 검수 필수 |
| 3 | 공개 데이터셋(Kaggle 등) | 겹치는 종만 보조 활용 | 라이선스 확인 |

도메인 갭 대응: 학습셋에 **실사용 유사 사진을 반드시 섞는다**. iNat 사진만으로 학습하면 실제 앱 사진에서 정확도가 떨어진다.

## 수집 목표 — MVP 우선 (확정: A-11)

**1차: 전 클래스 종당 250장 = 6,250장 (1~2일)** → 학습·평가 → **정확도 바닥인 종만** 아래 최종 목표까지 보강.
전량 수집 후 학습하면 피드백이 4일 뒤에나 온다.

`python -m src.config --summary` 로 항상 최신 현황(MVP/최종/현재 raw)을 본다.

| 난이도 | 최종 목표 | 해당 클래스 |
|---|---|---|
| easy | 350장 | 돌돔·참돔·광어·쏘가리·배스·블루길·가물치·메기·동자개·갈치·방어·피라미·송어 |
| medium | 600장 | 고등어·삼치·전갱이·숭어·농어·벵에돔 |
| hard | 1,000장 | 붕어·잉어·감성돔·우럭·볼락, **기타** |

최종 총합 14,150장(어종 13,150 + 기타 1,000).

## `기타` 클래스 수집 (25번째, 인덱스 24)

비물고기·24종 밖 어종을 흡수하는 클래스다. **여기가 부실하면 고양이 사진이 "붕어 0.7"로 나온다.**
한 종류에 쏠리지 않게 골고루 모으는 것이 핵심 — 요리 사진만 1,000장 넣으면 "요리가 아닌 비물고기"를 못 거른다.

| 구성 | 비중 | 예시 키워드 |
|---|---|---|
| 24종 밖 어종 | 40% | 향어, 학꽁치, 붕장어, 우럭볼락, 대구, 갑오징어, 문어, 게 |
| 조리·시장 사진 | 20% | 회 접시, 생선구이, 어시장, 수산시장 |
| 낚시 관련 비물고기 | 20% | 낚시터 풍경, 낚싯대, 루어, 릴, 뜰채, 쿨러 |
| 일반 오촬영 | 20% | 사람, 손, 바닥, 하늘, 반려동물, 음식 |

- `iNaturalist`에서 학명으로 못 긁으므로 대부분 검색 크롤링으로 채운다 (`config.SPECIES["기타"].scientific == ""` → 크롤러는 이 클래스를 건너뛰도록 분기).
- 실제 앱 사용자가 잘못 찍을 법한 사진을 상상해서 넣는 게 가장 효과적이다.

## 검수 기준 (삭제 대상)

- 요리·회·조리된 사진, 어시장 진열 사진
- 여러 마리가 겹쳐 나온 사진 (한 마리가 명확히 주인공이면 유지)
- 일러스트·도감 그림·워터마크 큰 사진
- 다른 종 (특히 혼동 쌍: 붕어/잉어, 우럭/볼락, 감성돔/벵에돔)
- 물고기가 화면의 10% 미만인 원경 사진
- 손상 파일 (열리지 않음)

**유지할 것**: 손에 들고 찍은 사진, 바닥/뜰채/쿨러 위 사진, 젖은 상태, 역광, 흐릿한 폰카 사진 — 실사용 분포와 같다.

속도 팁: 윈도우 탐색기 '아주 큰 아이콘' 뷰로 훑으면 시간당 1,000장 정도 검수 가능.

## 분할 규칙 (`split.py`)

- 종별 stratified 70/15/15, 시드 고정(42).
- **같은 관측(observation)에서 나온 사진은 같은 split에 몰아넣는다.** iNat는 한 개체를 여러 각도로 찍은 사진이 묶여 있어, 나누면 test셋이 오염되어 정확도가 부풀려진다. 파일명 `inat_<obsid>_<photoid>.jpg` 의 obsid로 그룹핑.
- 웹 크롤링 사진도 dedup 후 남은 유사본이 split을 넘나들지 않도록 phash 근접 그룹 단위로 배정.
- 분할은 **복사**가 아니라 파일 이동/하드링크로. 디스크 3배 낭비 방지.

## 라이선스 기록

`data/licenses.csv` 에 이미지 단위로 남긴다:

```csv
filename,species,source,source_id,license,author,url,collected_at
inat_12345_67890.jpg,붕어,inaturalist,12345,cc-by-nc,someone,https://...,2026-08-13
```

- 공모전 제출 시 데이터 출처 근거로 쓴다.
- 상업 전환 시 CC0/CC-BY만 남기고 재필터링하려면 이 파일이 필수다 ([decisions.md C-8](decisions.md)).
- 검색엔진 크롤링분은 `license` 를 `unknown` 으로 표기.
